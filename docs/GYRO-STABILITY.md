# 陀螺仪高转速"乱飞"：控制律离散化 + 限幅修复（2026-10-18）

> 反馈原话：**「陀螺仪在高转速下放到载具上，如果载具不是平稳状态，那么载具就会乱飞，
> 低转速没什么问题」**
>
> 本轮只动 `content/contraptions/gyro/**`、`config/CWServer.java`（追加）、`tools/**`、`docs/**`。
> 旧版对照：`Clockwork-1.20.1-main/common/.../physicalities/gyro/GyroShipControl.kt`（VS2 版）。
> Sable 侧的接口用 `javap` 对着**实机在用的** `mods/sable-neoforge-1.21.1-2.0.6.jar` 核实；
> `Create-mc1.21.1-dev/` 只读参照（其 `AGENTS.md` 不接受 LLM 贡献，未做任何修改）。

## 1. 症状为什么指向"离散化不稳定"

"低转速正常 / 高转速乱飞 / 载具必须本来就不平才会发作"这三条合起来，几乎只能是
**增益随转速升高、在高增益处离散闭环不稳定**：

| 观测 | 对应的机制 |
|---|---|
| 低转速没问题 | 低转速时 `speedToForce` 只有 0.3~2，"每子步消掉的误差比例" k 很小 |
| 高转速乱飞 | k 随转速升到接近 1 甚至 >1，负反馈变成正反馈 |
| 载具平放时没事 | 水平姿态是控制律的**不稳定平衡点**：误差为 0 时不出力，所以只有带倾角（或刚被外力踹过）才发作 |
| 不是"某个方向错" | 方向错的话低转速也会往错的方向倒 |

## 2. 旧版控制律逐项对照（`GyroShipControl.kt`）

| 项 | 旧版（1.20.1 + VS2） | 本移植（修前） | 量化结论 |
|---|---|---|---|
| `up` 方向 | `R·shipUp`，:51 | `orientation·localUp` | 一致 |
| 偏离自转轴分量 | `ω − up·(ω·up)`，:52-53 | 同 | 一致（D 项就在这里） |
| 期望角速度 | `up × (0,1,0) − ω⊥`，:54 | 同 | 一致；大小 = sin(倾角) ≤ 1 rad/s |
| 力矩 | `R·(I·(R⁻¹·ω理想))`，:56-58 | `I_local·R⁻¹·ω理想`（等价） | 一致（Sable 收 local 系） |
| 强度曲线 | `128/(1+e^(6−0.05·RPM))` 截到 0..100，:65-68 | 同（×`gyroStrength`，默认 1.0） | 一致；145 RPM 触顶 100 |
| 限幅 | **无** | `gyroMaxTorque = 2e6 N·m` | 2e6 对 10³~10⁴ kg·m² 的结构相当于 10²~10³ rad/s²，**挡不住振荡** |
| D 项独立系数 | 无（与 P 同系数 s） | 无 | 连续域 ζ=√s/2，是**过阻尼**，不是"缺 D" |
| 施加频率 | 每物理刻 1 次（`applyWorldTorque`） | 每物理子步 1 次，力矩 ×dt 转角冲量 | 乘 dt 是对的（`CWForces.java:48-51`），**不乘会随子步数放大** |

**真正的差异在第 8 行**：旧版把这条律当**连续力矩**交给 VS2 的求解器；Sable 的路径是
`ForceTotal.applyTorqueImpulse` → `apply_torque_impulse`，即每个子步把 `τ·dt` 直接加到角速度上。
于是每个子步的等效比例是

```
修前（照抄旧版常数）：k = s·dt
修后（一阶 ZOH 精确解）：k = 1 − e^(−s·dt)
```

`dt = 1/20/substepsPerTick`。实机 `config/sable-server.toml` 写的是
`sub_level_substeps_per_tick = 2` → **dt = 25 ms**。
小角度把倾角 θ 与角速度 ω 写成状态、按 Rapier 的顺序（先加角冲量、再用新 ω 积分）离散化：

```
M = [[1 − dt·k, −dt·(1−k)],
     [k,        1−k       ]]      det = 1−k,  tr = 2 − k(1+dt)
ρ(M) ≤ 1  ⟺  k ≤ 4/(2+dt) ≈ 2
```

修前 `speedToForce(256 RPM) = 100` → **k = 2.5 > 2 → ρ = 1.538**（每子步放大 1.5 倍且**每步反号**）。
`ρ` 越过 1 的门槛对应输入轴 **≈130 RPM**（dt=1/40）；这正是"低转速没事、高转速乱飞"的分界，
而 128 RPM 时 k=1.92 只是**贴着边界**（力矩已经开始在 Nyquist 频率上正反抽打，
实机上表现为剧烈抖动）。

> 说明：VS2 core 是二进制依赖，本地没有它的 tick 频率，因此**不能**断言旧版在 VS2 下一定稳；
> 能确认的是**同一套常数在 Sable 的显式角冲量路径 + 25 ms 子步下必然不稳定**，
> 而修前的 128 RPM 已经在稳定边界上。真正的差异是积分器/后端，不是公式抄错。

## 3. 修法

`GyroBlockEntity#sable$physicsTick`：

1. **ZOH 精确离散化**：`Δω = (1 − e^(−s·dt))·ω理想`，再 `τ_local = I·R⁻¹·Δω/dt`。
   k 恒 ∈ (0,1)，对任意 s、任意 dt 收敛；`s·dt ≪ 1` 时与旧版逐项一致（中低转速手感不变）。
2. **按角加速度限幅**（新配置 `attitude.gyroMaxAngularAcceleration`，默认 20 rad/s²，≤0 = 不限）：
   `|Δω| ≤ α_max·dt`。相对惯量封顶，大小结构手感一致；这是"失控时不被弹飞"的主限幅。
   原 `gyroMaxTorque`（2e6 N·m）保留为绝对兜底。
3. **多陀螺摊薄**：Sable 在一个子步里先跑完所有 actor 再统一 `applyQueuedForces`
   （`ServerSubLevel.java:279-287`），N 块陀螺读到同一份起始角速度 → 总增益是 **N·k**。
   按块数除以 N 后总增益恒为 k，等价于旧版"每条船只挂一个 `GyroShipControl`"的权限；
   否则 3 块以上在高转速会重新越过 k≤2 的界（仿真 S6b 复现）。
4. **NaN 守卫**：惯量张量非有限时这一子步不出力 —— 把 NaN 塞进 Rapier 会被 Sable
   判成非法姿态并**直接删掉子空间**。
5. 注释里写清每一项的职责、单位（s 是 1/s，τ 是 N·m，α 是 rad/s²）与旧版行号。

## 4. 证据：离线仿真（`tools/gyro_stability_sim.py`）

模型：一阶刚体（各向同性 I=2000 kg·m²，另用 20000 复核），Rapier 同序积分
（先角冲量、再用新 ω 积分姿态），工况 = RPM{16…256} × 倾角{0°,5°,15°,30°} × dt{1/20,1/40,1/160}，
仿真 8 s。判定：`DIVERGED` = 峰|ω|>20 rad/s、翻过 120°、或跑完 8 s 还在 >1 rad/s 地转。

修前（旧版增益 + 现有 2e6 N·m 上限，dt=1/40）：

| RPM | 初始倾角 | 峰\|ω\| | 峰倾角 | 峰值力矩 | 判定 |
|---|---|---|---|---|---|
| 96 | 30° | 0.48 rad/s | 29.5° | 2.96e4 | 收敛 |
| 128 | 30° | 0.96 rad/s | 28.6° | 7.66e4 | 收敛（贴边界，Nyquist 抖动） |
| 192 | 30° | 14.7 rad/s | 179.7° | 2.0e6（撞上限） | **发散/翻覆** |
| 256 | 30° | 14.7 rad/s | 179.7° | 2.0e6 | **发散/翻覆** |

84 例统计：**修前 DIVERGED 20 例**（全部集中在 ≥128 RPM；默认 dt=1/40 时 192/256 RPM 有 6 例翻覆，
128 RPM 只在 dt=1/20 的子步数下翻覆）。"被外力踹一脚"（初始 20° + 3 rad/s 横滚）：修前 192/256 RPM
翻到 144.8°，**修后全部 0.01° 回正**。

修后：**84/84 全部 SETTLED**；≥128 RPM 末倾角 ≤5°，峰值力矩被 α 上限压在
`α_max·I`（20×2000 = 4.0e4 N·m），不再出现 2e6 那种"抽打"。
dt 无关性：同一工况在 dt=1/20、1/40、1/160 下的末倾角极差 **0.001°**（说明 timeStep 缩放正确）。

`python tools/gyro_stability_sim.py` 可复现上述表格；`--selftest` 是守门用的断言
（已挂进 `tools/run_gates.ps1 -SelfTest`）：

* S1 修后全工况收敛；S2 修后 ≥128 RPM 末倾角 ≤5°；
* S3 **修前 256 RPM/30°/dt=1/40 必须判为 DIVERGED**（防止有人把控制律改回去而不自知）；
* S4 修后 dt 无关；S5 解析谱半径（修后 ≤1、修前 >1）；
* S6 多陀螺；S7 脚本常数 / ZOH / 新配置与 Java 源码一致。

## 5. 参数与调参

| 配置 | 默认 | 作用 |
|---|---|---|
| `attitude.gyroStrength` | 1.0 | 乘在 0..100 的转速曲线上（单位 1/s）；想让陀螺更柔和就调小 |
| `attitude.gyroMaxAngularAcceleration` | 20 rad/s² | 陀螺合计允许给结构带来的最大角加速度（多块时按块数摊薄）；≤0 = 不限（不推荐） |
| `attitude.gyroMaxTorque` | 2e6 N·m | 绝对兜底，正常结构不会触到 |

## 6. 需实机确认

1. 低转速（16~32 RPM，安山/黄铜轴）平放/倾斜：应和以前一样"软"，无高频抖动。
2. 中转速（64~96 RPM）：倾斜 15°/30° 放手，应 2~3 s 内回平，不振荡。
3. **高转速（128/192/256 RPM）+ 倾斜 30°**：重点验收项，修前必翻，修后应平稳回平。
4. 高转速下用外力（撞击/糖火箭偏心）踹一脚：应被拉回，不出现"越修越晃"。
5. 多块陀螺并排（2/4 块）高转速：应平稳（权限不叠加，等价于 1 块）。
6. 红石倾斜（四向模拟杆）：俯仰/横滚方向仍与旧版一致。
